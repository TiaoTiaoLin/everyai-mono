## Design

All new files go in `lib/features/code/drivers/` unless noted. Keep each file small.

### 1. `driver.dart`

```dart
enum DriverCap { steer, fork, rewind, resume, subagents, approvals, perCallApprovals, usage, mcp, skills, images, switchModel, effort }
@immutable final class DriverInfo { const DriverInfo({required this.id, required this.label, this.needsConsent = false}); … }
@immutable final class DriverStatus { installed, String? path, String? version, bool? signedIn /* null: unknown */, String? problem; static const notBuilt = …; }
@immutable final class DriverModel { id, label, bool isDefault, List<String> efforts }
abstract interface class HarnessDriver implements Harness {
  DriverInfo get info; Set<DriverCap> get caps; Future<DriverStatus> detect(); Future<List<DriverModel>> models();
}
@immutable final class DriverBriefing { mcpUrl, mcpToken, skillDir, sessionSkill }   // used by SessionSpec.briefing
```

- `DriverBriefing` lives here, not in `drivers/briefing/` (s1 owns that folder). `SessionSpec` gets
  `final DriverBriefing? briefing;` (null for EveryAI). `harness.dart` imports `drivers/driver.dart` for the type.
  Alternatively, put the class in `harness.dart` to avoid the import direction harness→drivers. **Prefer
  `harness.dart`**: `SessionSpec` lives there and nothing else in it depends on drivers, and `driver.dart`
  re-exports it.
- **New markers in `harness.dart`** (next to the existing ones):
  - `ForksSessions { Future<HarnessSession> fork(String parentConversationId, SessionSpec spec); }` at the harness
    level. `EveryAIHarness` (io and stub) implements it. `forkSession` becomes `h is ForksSessions ? h.fork(…) :
    null`. This removes the `impl.EveryAIHarness` type test and keeps forks working through the wrapper.
  - `SteersRuns { Future<void> steer(String text, {List<String> images}); }` at the session level. Nobody
    implements it in run 1; Codex/Claude lanes may.
- **`EveryAIDriver implements HarnessDriver, ForksSessions`** in `drivers/everyai_driver.dart`. It forwards to
  the `Harness` it wraps (`ref.read(everyaiHarnessProvider)`). `fork` forwards to `forkSession(inner, …)`.
  - `caps` = `{fork, rewind, resume, subagents, approvals, perCallApprovals, usage, mcp, skills, images,
    switchModel, effort}`. No `steer`: there is no native steer, and the fallback is today's behaviour. `fork` is
    derived as `inner is ForksSessions`. `perCallApprovals` is the static claim of what `EveryAISession`
    implements.
  - The controller keeps reading the session markers at runtime: `perCall => _session is PerCallApprovals`,
    unchanged. The static set serves pre-session needs (new-session sheet, policy, fidelity label).
  - A test pins the two together: a started EveryAI session `is PerCallApprovals`/`CompactsInPlace` iff the caps
    say so.
  - `detect()` → installed, version = app version (or null), no problem. `models()` → `[]` (the app's model
    catalog serves EveryAI; e2 decides).

### 2. `driver_policy.dart`

Pure functions, no Riverpod:

- `HarnessError forkUnavailable(DriverInfo i)` →

  summary). `CodeSessions` (l.540) uses `forkSession(...) ?? (caps.contains(fork) ? … : throw forkUnavailable)`

- `String? rewindRefusal(DriverInfo i, Set<DriverCap> caps)` → plain text such as
  `"${i.label} can't go back to an earlier turn. Start a new session from here instead."`, or null. `rewind()`
  returns `RewindOutcome.failed(msg)` first thing, before stop and git.
- `bool usesOurChildSessions(Set<DriverCap> caps) => !caps.contains(DriverCap.subagents)`. This is a flag with no

- `bool autoDecidable(ActionCall c)`: the action kinds the policy understands (`TerminalAction`, the file
  edit/read kinds, `MCPToolAction`, client tools, and the read-only kinds of `AgentMode.isReadOnly`). For a
  **non-EveryAI driver** the controller treats any other kind as "ask the user" (a null verdict) in

- The controller gets `Set<DriverCap> get _caps` and `DriverInfo get _driverInfo` from
  `ref.read(driverRegistryProvider).resolve(info.harness)`. The demo path resolves `everyai`, as its stored name
  is `everyai`.

### 4. `json_rpc.dart` + `driver_process.dart` (`_io` / `_stub`)

- **`json_rpc.dart`** is pure Dart, with no `dart:io`, so the replay kit and web builds compile.
  - Interface: `abstract interface class LineChannel { Stream<String> get lines; void send(String line); Future<void>
    close(); }`.
  - Peer: `final class JsonRpcPeer { JsonRpcPeer(LineChannel ch, {Future<Object?> Function(String method, Object?
    params)? onRequest, void Function(String method, Object? params)? onNotify, bool writeVersion = true}); Future<Object?>
    request(String method, [Object? params, Duration timeout]); void notify(String method, [Object? params]);
    Future<void> get done; Future<void> close(); }`.
  - Behaviour:
    - ids are ints
    - it skips non-`{` lines and bad JSON
    - responses are matched by int or string id
    - a server→client request goes to `onRequest`: its result becomes `result`, a thrown `JsonRpcError(code,
      message, data)` becomes `error`, and with no handler it replies -32601 (today's MCP behaviour)
    - when the channel ends, every pending request fails with `JsonRpcError` carrying the channel's last stderr
      line (supplied by the channel)
- **Port `_StdioMcp` onto it.** `_StdioMcp` becomes "spawn + `JsonRpcPeer`". It keeps its `McpError` texts by
  mapping `JsonRpcError`→`McpError` in `_resultOf` and the timeout message. That removes ~50 duplicated lines.
  Covered by `everyai_harness_test.dart:629`. If the port isn't clean (error text drift), leave `_StdioMcp` alone
  and say so in the commit. Don't half-share it.
- **`driver_process.dart`** has the public API and `driver_process_io.dart` / `_stub.dart` the implementation, in
  the style of `session_processes.dart`:
  ```dart
  Future<DriverProcess> spawnDriver({required String executable, required List<String> args, required String cwd,
    required String sessionTag, required String logPath, Map<String, String> env = const {}});
  abstract interface class DriverProcess implements LineChannel { int get pid; Future<int> get exitCode; String get stderrTail; }
  Future<DriverStatus> detectCli(String command, {List<String> versionArgs = const ['--version']});
  ```
  - io: `Process.start(executable, args, workingDirectory: cwd, environment: {...ShellEnv.load().env, ...env,
    sessionEnvVar: sessionTag})`, with no `runInShell`: `detectCli` resolved the absolute path on the login-shell
    PATH.
  - stdout goes through `utf8` + `LineSplitter`. stderr is appended to `logPath` (an `IOSink`, created under the
    session dir) and keeps a 2 KB tail.
  - `close()`: unregister, then `killTree(pid)`.
  - `detectCli` resolves the command with `which` under `ShellEnv`'s PATH (a GUI app doesn't inherit the user's
    PATH), runs `--version` with a 10 s timeout, and returns the first line. `signedIn` stays null; drivers add
    their own probe (claude: `claude auth status` → `loggedIn`).
  - The stub throws `HarnessError('Outside agents run on the desktop app.')`, and `detectCli` → `DriverStatus(problem:
    'Needs the desktop app.')`.
- **Making Stop and the Processes pane own the tree.** The env var alone is not enough (see Problem):
  - add a registry in `session_processes.dart`: `registerDriverRoot(String tag, int pid)` /
    `unregisterDriverRoot`, called by `spawnDriver` and `close`
  - `ProcessTable.sessionProcesses(…, roots: {pids})` treats each root like a tmux shell: its descendants are the
    session's, and the root itself is spared, so Stop kills the CLI's tools, not the CLI
  - `killSessionProcesses`/`findSessionProcesses` pass `driverRootsOf(tag)`
  - after an app crash, an orphaned CLI (ppid 1, tag visible) is already swept as an orphan

  This touches `harness/session_processes*.dart`, which no other lane owns.

### 5. `test/support/replay_transport.dart`

- **`ReplayChannel implements LineChannel`**, built from a `.jsonl` file or a string. Each line is `{"dir":"in"|"out",
  "msg":{…}}`, where `in` = from the agent to us and `out` = from us to the agent.
  - On start and after each matched `out`, it emits every following `in` line.
  - `send(line)` compares with the next `out` using a tolerant matcher:
    - JSON-RPC `id`s are learned, so a recorded id maps to ours and later `in` responses are rewritten to our id
    - placeholder strings `"{{cwd}}"`, `"{{session}}"`, `"{{any}}"` match anything and bind cwd/session for
      substitution in later `in` lines
    - object key order is ignored
  - A mismatch throws a `TestFailure` naming the line number and the first differing path.
  - `Future<void> get finished` completes when the script is consumed. `expectFinished()` fails when `out` lines
    are still waiting.
- **No timing.** Messages flow as fast as the peer reads, with no delays.
- **Self-test:** `test/features/drivers_replay_test.dart` plays a small hand-written fixture through `JsonRpcPeer`
  (initialize request/response, a server notification, a server→client request answered by `onRequest`, plus one
  deliberate mismatch that must fail).
- HTTP replay (OpenCode `serve`) is left to o1. `package:http/testing` `MockClient` covers it without a shared
  kit.

### 6. `UsageReport`

- **Event.** In `events.dart`: `final class UsageReport extends HarnessEvent { input, output, cached, int?
  costMicros, bool onPlan }`.
  - Decoded from `kind: 'UsageReport'` (raw keys `input_tokens, output_tokens, cached_tokens, cost_micros,
    on_plan`), with a `UsageReport.of(...)` factory that builds `raw`, so the remote mirror carries it.
  - Semantics, to be stated in the doc comment: **one model call or turn, as a delta**. `input` **includes**
    cached tokens, as in `UsageTotals.promptTokens`. Drivers convert cumulative counters (Codex totals, Claude
    `result`) to deltas and normalise cache reads in.
  - The id must be stable across replay.
- **Fold.** `transcript.dart:406` adds `UsageReport()` to the ignored case.
  - The controller: `if (event is UsageReport) ref.read(codeUsageProvider(sessionId).notifier).report(event)`.
  - `CodeUsage` keeps `_reports = <String, UsageReport>{}`, keyed by event id, so a replay after a controller
    rebuild doesn't double count (an empty id is counted live only). Its value = backend totals + `_local`.
  - `_local` folds with `addCall(prompt: input, completion: output, cached:, ownKey: onPlan ? 0 : costMicros ?? 0)`.
    A cost paid on the CLI's own API key counts toward the budget like BYOK.
  - `onPlan` cost goes to a new `UsageTotals.planMicros` (shown, never in `spentMicros`), since a subscription
    isn't spend. Add it to `toJson/fromJson/==/hashCode/+/addCall`.
  - `_fetch` keeps running for EveryAI. For other drivers it may skip the GET (`info.harness != everyai` →
    `UsageTotals.zero` base). EveryAI emits no `UsageReport`, so its path is unchanged.

### 8. Approvals for any driver

- **Contract (doc comment on `HarnessDriver`).** Drivers emit `ActionCall`s with our action kinds:
  - shell → `TerminalAction{command}`
  - edits → `FileEditorAction{command: create|str_replace…, path}` or `WriteFileAction/EditAction{path}`
  - reads → `ReadFileAction{path}` / `GrepAction` / `GlobAction`
  - MCP → `MCPToolAction` with the tool name
  - anything else keeps its native `kind` and gets asked

  The native name goes in `toolName`. An approval is that call without a result plus
  `StateChange(waiting_for_confirmation)`. `respond(callIds)` maps back to the native reply. Drivers whose
  rejections don't park the run make `resume()` a no-op.
- **Helper.** A small `drivers/driver_events.dart` `actionEvent({id, toolName, toolCallId, kind, args})` /
  `resultEvent(...)` / `waiting()` builds the raw OpenHands JSON and decodes it, so the five lanes don't each
  hand-roll the shape. It's about 30 lines.
- **Controller:** the `autoDecidable` gate for non-EveryAI drivers (§2). Everything else (floor, deny/allow rules,
  danger classifier, Plan refusal, `_mustWait`, budget) already runs on any `ActionCall`.

## Simplicity check

- **Overengineering risks, and the cuts:**
  - Don't model t3code's grouped capability struct. A flat `Set<DriverCap>` is enough.
  - Don't add a parallel event model. `UsageReport` is the only new event.
  - No HTTP replay kit.
  - No caps derivation magic. The markers stay the runtime truth, and one consistency test covers them.

  - The `autoDecidable` gate closes a Full auto hole.

## Risks

- **Fork regression** if `ForksSessions` isn't applied to both `everyai_harness_io.dart` and `everyai_stub.dart`.
  Add a test: `forkSession(EveryAIDriver(...))` is non-null.
- **Import cycle.** `harness.dart` must not import `drivers/`. Put `DriverBriefing` in `harness.dart` (or a
  leaf file) and have `driver.dart` import harness, not the reverse.
- **Process roots registry is in-memory.** After an app restart, the CLIs are gone or orphaned. Orphans are swept
  by tag, so this is fine, but the app should also close live driver processes on quit (the sidecar used an
  `AppLifecycleListener`; check what the EveryAI harness does now). Stop sparing the root means a CLI blocked in
  its own loop keeps running until `interrupt` lands.
- **macOS `ps -E`** hides the env of system binaries, so a `bash` started by the CLI shows no tag. The roots
  approach doesn't depend on env visibility, which is one more reason for it.
- **Usage persistence.** External drivers don't replay history the way the EveryAI harness does. If their events
  (including `UsageReport`) aren't journalled locally, the meter and transcript are empty after a restart. Each
  run-2 driver needs a local event journal. Flag it to run 2: a shared `<sessionDir>/events.jsonl` writer could be
  a later d-item.
- **Codex framing** (`jsonrpc` field present or not) is unverified. `writeVersion` is an option, and reading is
  tolerant.
- **Spec drift:** Gemini 0.33.2's flag is `--acp` (`--experimental-acp` is deprecated).
- **Statuses per driver:** stub drivers return `{}`, so their sessions show no status in lists until run 2.
- **Test with a non-demo path:** a FakeHarness-backed driver needs a real tmp folder, so `_connect` runs
  `_openContext`/`_loadSettingsRules` for real. Keep the folder empty (no git) and override `gatewayKeysProvider`
  if `specFor` is reached. A seeded `code.sessions` + `attach` route avoids `specFor` entirely.
- Changing `steer`/`rewind` must keep `code_rewind_test.dart`, `code_session_commands_test.dart` and the
  everyai harness tests green.
